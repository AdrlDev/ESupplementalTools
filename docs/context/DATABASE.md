# Database

Room database: `AppDatabase`, file `esupplemental.db`, schema version `19`, `exportSchema = false`.

## Tables

```text
users
 ├── id (PK), name, email, passwordHash, createdAt
 └── used by UserDao/AuthRepository

user_stats
 ├── userId (PK), userName, level, levelProgress, songsCompleted,
 │   storiesCompleted, quizzesAverage, overallScore
 └── used by HomeDao, ProgressDao, QuizDao

media_items
 ├── id (PK), title, type, duration, transcript, media URLs/resources,
 │   story category/moral
 └── indexed by (type, title); used by media/home repositories

audio_stories
 ├── autogenerated id (PK), mediaId, remoteId, URL/file metadata,
 │   duration, word timings JSON
 └── indexed by mediaId; generated-audio cache/metadata

story_activities
 ├── mediaId (PK), reorderEvents JSON, multiple-choice JSON, openEnded JSON
 └── generated from story assets; used by story exercise and Story Order

song_activities
 ├── mediaId (PK), fillBlanks JSON, messageQuestion JSON
 └── parsed from song question/answer assets; used by the song challenge flow

quiz_history
 ├── autogenerated id (PK), userId, score, total, serialized answers,
 │   type, timestamp
 └── FK to user_stats.userId with CASCADE; used by quiz/progress flows

notes
 ├── id (PK), userId, title, note sections, keywords JSON, createdAt
 └── indexed by (userId, createdAt); user-scoped list/delete

games
 ├── composite PK (userId, id), catalogue metadata, difficulty, stars,
 │   isLocked, xpReward
 └── per-user game catalogue/progress
```

## Writes and transactions

- Registration uses `UserDao.registerUserWithStats` transaction.
- Quiz save uses `QuizDao.saveQuizResultAndUpdateStats` transaction: insert history, recalculate counts/average/level, update stats.
- Profile name update changes user and stats in one DAO transaction.
- Media seed uses `REPLACE` for media and story activities.
- Game catalogue sync uses `IGNORE`, so existing rows preserve progress but do not receive later catalogue metadata changes.
- Game result update takes max stars and max XP and unlocks the game.

## Migrations

Defined migrations are 15→16, 16→17, and 17→18. The database version is 19, with no visible 18→19 migration. Koin also enables `fallbackToDestructiveMigration(true)`, so an installation that needs the missing path may lose local users, notes, quiz history, game progress, and cached metadata. Schema export is disabled, which makes migration review harder.

## Storage caveats

- `audio_stories.mediaId` is indexed but not unique; the logical cache key is enforced only by lookup and an in-process mutex.
- `notes.getNoteById` is not user-filtered, although list/delete operations are user-filtered.
- JSON fields depend on Gson converters and are not independently queryable.
